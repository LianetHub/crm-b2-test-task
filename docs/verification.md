# Проверка реализации

Проверено 4 ноября 2026 года на Windows, Node.js 26.11.1, Docker Desktop и локальном Supabase CLI 3.0.0.

| Проверка               | Результат                                                                                            |
| ---------------------- | ---------------------------------------------------------------------------------------------------- |
| TypeScript             | `npm run typecheck` — успешно                                                                        |
| ESLint                 | `npm run lint` — успешно                                                                             |
| Форматирование         | `npm run format:check` — успешно                                                                     |
| Логика и PostgreSQL    | `npm test` — 17 тестов, включая матрицу из 50 сочетаний роли и перехода                              |
| Настоящий Supabase API | `npm run test:api` — 7 тестов с пользовательскими JWT                                                |
| Браузер Chromium       | `npm run test:e2e` — 2 сценария, полный цикл и мобильный вход                                        |
| Production-сборка      | `npm run build` — успешно; Vite сообщает о крупном общем JS-чанке                                    |
| Зависимости            | После фиксации исправленного minimatch 11.0.4 npm сообщает 0 известных уязвимостей                   |
| Миграции               | Обе миграции воспроизводятся на пустом PostgreSQL/PGlite; применены к настоящему локальному Supabase |
| Внешний деплой         | Не выполнялся: используется локальный Docker, публичный backend не настроен                          |

SQL-проверки охватывают прямую запись в таблицы, RLS для нескольких пользователей, неизменяемую историю, пустой комментарий, запрещённые переходы, переназначение, мягкое удаление и конфликт версий.

API-проверки дополнительно подтверждают фильтрацию вложенных запросов, отказ анонимному пользователю и пользователю без роли, бесполезность подмены роли через метаданные Auth, запрет регистрации и единственную запись истории при двух конкурирующих переходах.

Браузерный сценарий создаёт объект и задачу, воспроизводит конфликт правок двух постановщиков, выполняет цикл с доработкой и принятием, передаёт доступ при переназначении, удаляет объект и проверяет выход. Мобильная проверка охватывает неверный пароль и отсутствие горизонтального переполнения. Также визуально просмотрены десктопный список объектов и мобильная карточка задачи.

Независимая проверка кода обнаружила один существенный случай потери изменений в старой форме. Он исправлен второй миграцией с версиями записей, тремя SQL-регрессиями и браузерной проверкой сохранения актуального исполнителя. Других существенных замечаний не получено. Права администратора базы и публичная инфраструктура не рассматривались как часть защиты пользовательского API.
