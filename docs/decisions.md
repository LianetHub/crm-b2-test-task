# Решения и ограничения

## Согласовано

- Удаление мягкое: объект скрывается вместе с задачами, история не уничтожается.
- Исполнителя можно менять в любом статусе; статус не сбрасывается, доступ передаётся новому исполнителю вместе со всей историей.
- Полноценная реализация и проверка без строгого лимита в три часа.
- Supabase запускается локально в Docker, облачный проект для этого не требуется.

## Принято при реализации

- Одна компания и одна роль на пользователя. Все постановщики равноправны.
- Отдельного backend-сервера нет: проверки и транзакции выполняются в PostgreSQL.
- Все клиентские изменения выполняются только через RPC. Проверяющие функции находятся в закрытой схеме; RLS отвечает за чтение.
- Создание задачи добавляет начальную запись истории. Комментарий обязателен при возврате; для остальных переходов API допускает необязательный комментарий.
- Название и адрес объекта, название задачи и назначенный исполнитель обязательны. Описание необязательно.
- Автор и время назначаются базой. Имена участников фиксируются снимками, чтобы история оставалась понятной после изменения профиля.
- В принятой задаче постановщик может менять обычные поля и исполнителя, но не переоткрывать её: такого перехода в ТЗ нет.
- Перенос задачи между действующими объектами допустим для постановщика, статус и история сохраняются.
- Редактирование проверяет версию записи. Если другой пользователь успел изменить объект или задачу, старая форма не сохраняется; нужно открыть актуальную запись. Смена статуса также повышает версию задачи.
- Архив и восстановление не входят в интерфейс. Пользователей с историей не удаляем физически: внешние ключи защищают ссылки.
- Данные обновляются после изменений, при возвращении на вкладку и раз в 15 секунд. Серверный доступ отзывается сразу, уже показанные на экране сведения исчезают после обновления.

## Границы версии

- Нет уведомлений, вложений, сроков, общего чата, поиска и интерфейса управления пользователями — они не требовались.
- Для большого рабочего объёма понадобятся серверная пагинация интерфейса и агрегированные счётчики. Сейчас клиент получает доступные строки порциями по 500, затем отображает их целиком.
- Локальный Supabase CLI — среда разработки. Для публичного доступа требуется отдельный сервер с HTTPS либо облачный Supabase; открывать локальные служебные порты в интернет не предполагается.
- Публикация и URL репозитория зависят от выбранной пользователем внешней инфраструктуры. Секретные ключи и пароли не входят в исходники.
